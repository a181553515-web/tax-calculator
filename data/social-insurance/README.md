# 社保公积金政策数据维护规范

本目录存放社保公积金计算器的政策数据。它与计算引擎、页面展示分离，避免更新某个城市政策时误改计算逻辑。

## 状态定义

| 状态 | 页面行为 | 何时使用 |
| --- | --- | --- |
| `verified` | 可自动计算，并展示依据与有效期 | 小波财税已逐项核验基数、险种费率、公积金和适用范围 |
| `reference` | 只展示资料与官方链接，不计算 | 已收集部分官方信息，但不足以覆盖完整计算 |
| `expired` | 提示数据过期，不计算 | 原有政策已过有效期，等待新年度文件 |
| `manual` | 用户完整输入参数后可计算，并明确标注未核验 | 本地审核、特殊统筹区或临时测算 |

## 新增或更新一个地区的步骤

1. 收集该统筹区的人社、医保、税务、公积金中心官方文件；不要仅引用媒体整理或计算器页面。
2. 确认适用对象，例如“企业职工”“灵活就业人员”或“机关事业单位”。不同对象不能混用一条数据。
3. 录入参保地区、有效起止日期、完整费率、基数上下限、公积金比例范围与来源链接。
4. 将状态先设为 `reference`，完成第二人复核后才设为 `verified`。
5. 在 `tests/` 中增加该地区的下限、正常、上限三个计算案例。
6. 更新 `CHANGELOG.md`，注明影响地区、政策有效期和来源。
7. 运行 `node --test tests/*.test.js`，由小波财税审核通过后才允许推送生产分支。

## 必填字段

每条记录必须包含地区、适用范围、有效期、来源、复核日期、复核人和状态。`verified` 数据还必须包含完整的社保/公积金基数及费率。缺少任一项，页面不得自动输出缴费金额。

## 特别注意

- 同一省内存在多个统筹区时，必须拆成多条记录，不能用省级平均值替代。
- 工伤、长期护理险、大额医疗、生育和公积金执行口径经常存在地区差异；无法确认时应保留为 `reference`。
- 页面结果必须展示政策版本和来源，让用户与审核人员可以回溯。
