# 社保政策数据治理审核版设计

## 目标

把社保公积金计算器从“省级通用估算”调整为“按已核验参保地区计算，并清楚展示数据依据与适用范围”。计算器继续完全在浏览器本地运行，不收集工资、城市或计算结果。

## 方案比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 保留 31 省单一参数 | 改动最少、覆盖面看似最大 | 市级统筹差异与年度更新会直接造成错误结果 | 不采用 |
| 一次补齐全国全部市级数据 | 覆盖完整 | 数据核验和持续更新成本太高，首版难保证质量 | 暂不采用 |
| 核验地区优先、逐步扩展 | 可从服务区域开始，所有上线数据可追溯、可审核 | 初期覆盖范围较小 | 采用 |

## 审核版范围

1. 将政策数据从页面代码中拆到独立、可被浏览器直接加载的 JavaScript 数据文件；每项必须记录参保地区、适用对象、有效期、来源链接、核验日期与状态。
2. 首版只内置“参考资料”与需人工复核的政策记录，不再把旧省级数据描述成全国准确数据；未核验地区不会自动给出金额。
3. 保留“按当地通知手工录入参数”模式。它会明确标注为手工测算，不带任何地区名称或官方背书，方便审核期内继续核对计算引擎。
4. 页面改为先选“参保地区”，结果展示政策版本、适用范围及来源；将“个人到手工资”更正为“扣五险一金后工资（未扣个税）”。
5. 添加“继续计算个税”入口，只通过 `sessionStorage` 传递当前标签页数据，不把工资信息写进 URL 或分析参数。
6. 补齐搜索基础设施（规范网址、分享信息、站点地图）及明确的本地计算隐私说明。
7. 用 Node 内置测试覆盖数据完整性、未核验地区拦截、手工模式、已核验政策引擎和关键结果文案。

## 数据流

`social-policy-data.js` -> 页面初始化 -> 地区选择 -> 校验数据状态与有效期 -> `calcSI()` -> 结果卡片（金额 + 政策依据）

只有 `status: "verified"` 且当前日期处于 `effectiveFrom`、`effectiveTo` 期间的数据可以输出结果。`reference` 或 `expired` 数据会显示说明和来源，不输出估算金额。唯一例外是 `manual` 模式：用户填写完整参数后可以测算，但结果始终标明“手工录入参数，未经小波财税核验”。这条规则宁可减少覆盖，也避免把过期政策包装为精确结果。

## 数据结构

每条政策至少包含：

```json
{
  "id": "cn-fj-enterprise-2026-07",
  "label": "福建省（职工医保示例，待补齐其余险种）",
  "region": { "province": "福建", "city": null, "poolingArea": "省级" },
  "status": "reference",
  "scope": "企业职工；仅用于政策资料展示，不生成缴费金额",
  "effectiveFrom": "2026-07-01",
  "effectiveTo": "2027-06-30",
  "sources": [{ "title": "官方文件", "url": "https://..." }],
  "reviewedAt": "2026-07-23",
  "reviewedBy": "小波财税",
  "calculation": null
}
```

`verified` 数据才拥有完整 `calculation` 字段。这样新增城市不需要改计算器引擎，只需新增经过人工核验的数据记录和测试案例。

## 审核标准

- 不能再出现默认安徽并直接测算的行为。
- 任何展示金额的结果都能点开官方依据并看到有效期。
- 未核验城市不会给出看似精确的金额。
- 社保结果不得暗示已经扣除个人所得税。
- 用户输入及跨工具传参均不离开浏览器。
